# Continuous Quality Improvement Cycle

## Process: Retrospective

Note: Next Retrospective Finish Modelling This.

Once a week, perform a retrospective. By doing this first it 
ensures the thoughts are on the retrospective not the items.

```
«VALENCE»

**POSITIVE**
- Learnt a new programming language
- Devised a way to easily build self-hosted app server with
websocket
- DeepSeek is amazing for learning when its reasoning.

**NEUTRAL**
- Initiated Continuous Quality Management
- Began Literate Programming

**NEGATIVE**
- Need to restore my git workspace after removing items
- Need better balance.
- Need better managment of everything.
- OpenAI LLM is not useful and wastes time
```

Next, we go through the items identified.

```
## Action Items

[ ] Try Get DeepSeek AI to Finish the Specification

[ ] Consider Building Design Rubrics

[ ] Build Retrospective Process

[ ] Build Task Management Process

[ ] Explore Task Management

[ ] Focus on Literate Document to Design Workspace Rebuild

```


Lastly, go through the previous week retrospective action items,
that were not discussed. This is done last to allow fresh ideas
to be compared to ones in the week before.

```
«REVIEW PREVIOUS RETROSPECTIVE ACTION ITEMS»

    «Action Item»

        «ACTION ITEM STATUS»    «QUESTION»                         «RESPONSE»

        **COMPLETE**             Was it worth it?                   
                                 Any benefits?
                                 Any issues?
                                 Should we focus on this more?

        **NOT COMPLETE**         Why?
                                 Should it be worth persuing?
                                 Can it be done differently?
```
