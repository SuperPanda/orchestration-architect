
## Introduction

The _OA (Orchestration Architect) Programming System_ uses **literate writing** to *compose* source code and documentation.

### Purpose

The purpose of the OA Literate Program System is weave structured natural language to automate documentation and source code generation and maintenance.

### Requirements

* *Self-Assembly as a First-Class Feature* — Ensures the system can *orchestrate its own evolution*
* *Automated documentation* — Derivable schemas and literate programming ensures documentation *is a part of the system itself*
* *Uniform Design Constraints* — Ensures the architectural design decisions can enforce *axiomatic rules* through the entire systems for a cohesive and consistence interface.
* Transformable Between Versions — Ensures different implementations and versions can *evolve without breaking existing structures*
* *Minimal Representation for Non-Derivable Implementations*
* *Utilise Abstract Design Patterns* — Details implementation of architectural and abstract design patterns that would otherwise be implicit.
